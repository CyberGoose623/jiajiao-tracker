# 语文得分追踪

家教用的考试记录工具。记的不是分数，是**每个学生、每道小题的得分和失分原因**，以及这些失分在几次考试之间怎么变。

三个前提决定了它的样子：

**各校自己出卷，总分和难度都不同。** 直接拿总分画折线，看到的是卷子难易，不是学生的进步。所以跨考试一律只比得分率。

**一个老师带几个学生，一个学生有好几科。** 数据按「学生 + 模板」分组，语文和英语各算各的，两个学生之间也不混。

**错因比分数有用。** 错因是点选的标签，能统计、能排频次；自由文本做不到这一点。

纯前端，无后端，无数据库服务，无框架，无构建工具，无 CDN。克隆下来就能跑，断网也能用。

## 一、快速开始

### 方式 A：直接双击（只能看界面）

双击 `index.html`，能打开、能录入、能看图。

但浏览器对 `file://` 页面有两条硬限制，代码绕不过去：

1. **读不到仓库根目录的 `exam-templates.json` 和 `error-tags.json`**。应用会自动改用内置的预置数据，顶部弹一条说明条。想换模板就在设置页导入 JSON。
2. **Chrome / Edge 下 IndexedDB 被禁用**，数据只存在当前页面内存里，刷新就没了。Safari 一般允许，但不保证。

所以双击只适合先看一眼。**真要长期用，走方式 B 或 C。**

### 方式 B：本地起服务（验证全部功能）

```bash
python3 -m http.server 8000
```

浏览器打开 `http://localhost:8000/`。JSON 能读、IndexedDB 能存、Service Worker 能注册，离线也能测。

### 方式 C：GitHub Pages（推荐长期用）

见第二节。

> iPad 上打不开 `localhost`，所以只要用 iPad，就必须走 Pages 这条路。

## 二、部署到 GitHub Pages

### 1. 建仓库

1. 登录 GitHub，右上角 `+` → `New repository`。
2. 名字填英文，比如 `yuwen-tracker`。
3. 选 `Public`。**不要**勾 `Add a README file`。
4. `Create repository`。

### 2. 上传文件

点 `Add file` → `Upload files`，把项目里**所有文件和文件夹**拖进去。

必须落在**仓库根目录**，正确结构是：

```
仓库根/
├── index.html
├── styles.css
├── manifest.json
├── sw.js
├── exam-templates.json
├── error-tags.json
├── js/
├── icons/
└── README.md
```

⚠️ 如果变成 `仓库根/yuwen-tracker/index.html`，Pages 打开会 404，得删掉重传。

拖完点 `Commit changes`。

### 3. 开启 Pages

`Settings` → 左侧 `Pages` → `Source` 选 `Deploy from a branch` → `Branch` 选 `main`、目录 `/ (root)` → `Save`。

等一两分钟，顶部出现：

```
https://你的用户名.github.io/仓库名/
```

### 4. 更新版本后

改了代码或 JSON 再上传，如果界面没变，把 `sw.js` 里 `const CACHE = 'yuwen-v2';` 改成 `yuwen-v3`，强制换缓存。

## 四、日常怎么用

### 打开后先看最上面那条

顶部绿色条是**当前学生**。点它切换学生，或者新建学生。

换了学生，录入和分析都跟着换。所有图表只算这个学生的数据。

### 录一次考试

1. 录入页选模板。下拉框里分两组：**这个学生用过的**排上面，其他模板在下面。
2. 填考试名和日期。
3. 22 道小题全部列出来，**每道默认填满分**，只改答错的那几道。
4. 答错的题点右边「错因」，按分组点标签，可以多选。
5. 试卷照片可以挂**多张**（正面、反面、作文页），保存时自动压到长边 1600px。
6. 顶部实时显示总分和得分率。
7. 点「保存这次考试」。

保存的时候，**所有失分题会自动进错题本**，不用你一道道点。

### 看分析

分析页顶部先选「看哪份」——这个学生用过的模板排前面。

下面的五张图只统计**当前学生 + 当前模板**的考试。语文的图和英语的图完全独立，不会互相污染。

### 看错题

设置页 →「查看错题本」。按当前学生过滤，按时间倒序。

每条能看到题号、考什么、错因标签，点「看原卷」跳到那次考试的详情，试卷照片就在上面。

搞懂了的点「标记已掌握」，会收到列表底部，不占视线，统计里还留着。

## 六、模板和错因怎么改

### 在应用里改（推荐）

**设置页 → 试卷模板 → 编辑**，出来的是表单，不是 JSON：

- 模板名、科目、考试时长、备注
- 每个部分的名字，可以加部分、删部分
- 每个小题的题号、考什么、满分、维度、题型，可以加题、删题
- 顶部自动算「小题满分合计」，跟总分对不上会提示，点一下就同步

**设置页 → 错因词表 → 编辑**，也是表单：

- 按科目分组显示，每组能看到里面所有标签
- 加分组、加标签、点 × 删标签
- 科目字段决定这些标签在哪种模板里出现

全程不碰 JSON。

### 直接改文件（适合批量）

`exam-templates.json`：

```json
{
  "schemaVersion": 2,
  "templates": [
    {
      "id": "tpl-xa-g7-yuwen",
      "name": "西安-初中-语文",
      "subject": "语文",
      "totalScore": 120,
      "duration": 150,
      "note": "积累 20 + 阅读 50 + 写作 50",
      "sections": [
        {
          "id": "sec-jilei",
          "name": "一、积累和运用（20 分）",
          "items": [
            { "id": "i-1", "no": "1", "fullScore": 2, "dimension": "jilei", "type": "choice", "label": "字音字形" },
            { "id": "i-4", "no": "4", "fullScore": 4, "dimension": "mingzhu", "type": "written", "label": "名著阅读" },
            { "id": "i-6-1", "no": "6(1)", "fullScore": 2, "dimension": "jilei", "type": "blank", "label": "古诗文默写" }
          ]
        },
        {
          "id": "sec-xiezuo",
          "name": "六、写作（50 分）",
          "items": [
            { "id": "i-20", "no": "20", "fullScore": 50, "dimension": "xiezuo", "type": "essay", "label": "作文" }
          ]
        }
      ]
    }
  ]
}
```

字段规则：

| 字段 | 说明 |
| --- | --- |
| `id` | 模板唯一标识。改它等于新建，历史记录还挂在旧 id 上。 |
| `name` | 建议写成 `地区-学段-科目`，像「西安-初中-语文」。 |
| `subject` | 科目。**错因按科目挂**，写了英语就只显示英语的标签。 |
| `totalScore` | 总分，应等于所有小题 `fullScore` 之和。 |
| `sections[].items[].id` | 小题唯一标识，同模板内不能重复。 |
| `no` | 题号字符串，支持 `6(1)` 这种小题写法。 |
| `fullScore` | 小题满分，正数，可有小数。 |
| `dimension` | 见下表，只能是这七个之一。 |
| `type` | `choice` / `blank` / `written` / `essay`。作文必须标 `essay`。 |
| `label` | 这道题考什么，短，直接显示在录入页每行。 |

`dimension` 枚举：

`jilei` 积累和运用 · `mingzhu` 名著阅读 · `wenyan` 文言文阅读 · `xiandai` 现代文阅读 · `gushi` 古代诗歌鉴赏 · `xiezuo` 写作 · `shuxie` 书写卷面

> 名著是单列维度，不并进积累和运用。所以预置模板里 `jilei` 16 分、`mingzhu` 4 分，合起来才是「一、积累和运用」那 20 分。

`error-tags.json`：

```json
{
  "schemaVersion": 2,
  "groups": [
    {
      "id": "g-yw-wenyan",
      "subject": "语文",
      "name": "文言文",
      "tags": [
        { "id": "t-shiciyi", "name": "实词义项记错" },
        { "id": "t-xuci", "name": "虚词用法不清" },
        { "id": "t-fanyi", "name": "翻译漏关键词" }
      ]
    },
    {
      "id": "g-en-grammar",
      "subject": "英语",
      "name": "语法",
      "tags": [
        { "id": "t-en-tense", "name": "时态错" }
      ]
    }
  ]
}
```

规则：

- `group.subject` 决定它属于哪科，缺省当语文。
- `group.id` 和 `tag.id` 都不能重复。
- **改 `name` 没事，改 `id` 等于换了个新标签**，以前标过旧 id 的记录不会跟着变，统计里会分成两行。

### 改文件 vs 改界面

- 改文件、刷新 → 内容变了就以文件为准，覆盖应用里的版本。
- 在界面里改 → 存进浏览器，文件没变就不会被覆盖。
- 两边都改过，以**最近一次改动**为准。想稳一点，改完在设置页导出一份 JSON 当备份。

## 六、备份和恢复

**不能省。** Safari 会清理长期不访问的站点数据，清了就没了，没有云端兜底。

### 备份

设置页 →「导出全部数据」，下载 `语文数据-备份-2026-11-10.json`。

里面包含：所有学生、所有模板、错因词表、全部考试记录（含各自的模板快照和照片引用）、错题本。

「备份里包含试卷照片」默认勾着。照片转成 base64 塞进 JSON，文件会大一些；不想要照片就取消勾选。

超过 14 天没备份，进应用会弹提示。

### 恢复

设置页 →「导入备份」→ 选文件。**按 id 去重合并，不覆盖已有数据**：

- 同 id 的学生跳过
- 同 id 的考试跳过，保留本地那条
- 同 id 的模板跳过（想覆盖就用「导入 JSON」单独导）
- 同 id 的错因组会合并标签，本地没有的补进去
- 照片按 id 去重

导入完会弹汇总，告诉你加了几条。

### 换设备

旧设备导出 → 传到新设备 → 新设备打开 Pages 地址 → 导入。

应用没有任何联网上传行为，这是设计要求，不是缺陷。

## 七、数据存在哪儿

全部在浏览器的 IndexedDB 里，库名 `yuwen-tracker`，七个表：

| 表 | 存什么 |
| --- | --- |
| `students` | 学生 |
| `exams` | 每次考试（含模板快照、逐题答案、照片 id 数组） |
| `templates` | 试卷模板 |
| `tagGroups` | 错因词表 |
| `mistakes` | 错题本 |
| `images` | 试卷照片（Blob） |
| `meta` | 上次备份时间、当前学生、文件同步指纹 |

没有 localStorage 存主数据，没有网络请求。

### 一条考试长什么样

```json
{
  "id": "exam-2026-11-05",
  "date": "2026-11-05",
  "name": "初一期中考试",
  "studentId": "stu-a1b2c",
  "templateId": "tpl-xa-g7-yuwen",
  "templateSnapshot": { "…录入当时模板的完整深拷贝…" },
  "answers": [
    {
      "itemId": "i-1", "no": "1", "dimension": "jilei",
      "fullScore": 2, "gotScore": 0,
      "errorTagIds": ["t-yinxing", "t-cuxin"], "note": ""
    }
  ],
  "essayLevel": 2,
  "paperImageIds": ["img-1", "img-2"],
  "createdAt": 1730000000000
}
```

`templateSnapshot` 是必须的。模板以后怎么改，这条记录都按当年那份算，前后对比才成立。

## 八、错题本是自动的

保存一次考试，**所有失分题自动生成错题记录**，字段是：

```json
{
  "id": "err-…",
  "examId": "exam-2026-11-05",
  "studentId": "stu-a1b2c",
  "itemId": "i-12",
  "no": "12",
  "label": "材料比较",
  "question": "第 12 题 · 材料比较",
  "myAnswer": "",
  "correctAnswer": "",
  "errorTagIds": ["t-jiaodu", "t-yuanwen"],
  "howToFix": "",
  "auto": true,
  "mastered": false,
  "resolved": false,
  "createdAt": 1730000000000
}
```

规则：

- **同一道题只生成一条**，重复保存不会重复堆。
- 你后来把某道题从失分改成满分，对应错题标 `resolved`，不删。手写的「正确答案」「怎么改」不会因为改个分数就没了。
- 「题干」「我的答案」「正确答案」「怎么改」留空让你自己补，`question` 自动填好题号和考点。
- 标记「已掌握」的收进列表底部，统计里还留着。

## 九、怎么算的

**得分率 = 该题得分 ÷ 该题满分。**

**维度得分率按满分加权：**

```
维度得分率 = Σ(该维度所有小题得分) ÷ Σ(该维度所有小题满分)
```

不是把小题得分率取平均。2 分的默写和 16 分的阅读简单平均会严重失真：2 分题拿 0、16 分题满分，加权是 18/20 = 90%，简单平均只有 50%。

**跨考试一律用得分率。**

**排除作文**：打开后 `xiezuo` 维度整体丢弃，总分、得分率、所有图重算。作文 50 分权重太大，会把别的维度压平。

**作文档位**：一类 45-50、二类 40-44、三类 35-39、四类 30-34、五类 29 以下。没手选就按作文得分折算。

**历史只认快照**：每条记录自带 `templateSnapshot`，模板怎么改都不影响它。

## 十一、从旧版本升级

如果你之前用过单学生版本，直接覆盖文件就行，启动时会自动迁移：

- 建一个默认学生，把原来的考试全挂上去
- `paperImageId`（单张）转成 `paperImageIds`（数组），一张不丢
- 错因分组没有 `subject` 的，一律归到语文
- 某道题从失分改成满分的旧记录，补上 `mastered` / `resolved` 默认值

迁移是幂等的，重复启动不会反复改。

## 十二、已知限制

1. **`file://` 双击**读不到根目录 JSON，Chrome 系还禁用 IndexedDB。应用会明确提示并降级，但刷新丢数据。
2. **Safari 会清本地存储**。备份是唯一保险，每月导一次。
3. **Service Worker 需要 https 或 localhost**。Pages 是 https，没问题。
4. **不做的功能**（按需求明确排除）：账号登录、多用户账号、权限、云同步、拍照 OCR、AI 评分、内置题库、学生端家长端分开。
5. 删学生会连带删掉该学生的考试和错题，删除前会明确告诉你数量。
6. 照片用 canvas 压缩，超大图（12000px 扫描件）在旧 iPad 上会慢一两秒。

## 十三、自测

前两套不需要装依赖：

```bash
node tests/selftest.js    # 101 项：计算规则、学生/科目隔离、自动错题、静态资源
node tests/smoke.js       # DOM id、样式类、脚本顺序、禁止项
```

第三套是端到端，先装两个开发依赖（不进仓库，不影响应用运行）：

```bash
npm install jsdom fake-indexeddb --no-save
node tests/e2e.js         # 67 项：真加载页面跑完整流程
```

`selftest.js` 覆盖：模板结构、分数合计、维度口径、加权得分率与简单平均对比、排除作文重算、作文档位、快照隔离、按学生过滤、按模板过滤、学生间互不影响、科目错因不串、自动错题生成与去重、改满分标 resolved、空数据不报错、资源相对路径、无 CDN、manifest 图标、SW 预缓存清单。

`e2e.js` 覆盖：启动、默认学生、题目行与默认满分、自动错题落库、错因按科目过滤、多图字段、分析页按模板过滤、新建学生后统计隔离、切回原学生数据还在、英语模板与语文数据不混、表单式模板编辑器、表单式错因编辑器、备份含学生、空状态、`file://` 兜底。

界面视觉和 iPad 真机手感要在浏览器里手工验。
